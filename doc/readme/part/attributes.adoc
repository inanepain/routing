= Overview of Attributes
:revnumber: 1.5.0
:revdate: 2026-10-13

What is an *Attribute*? It's a class just like any other class only with the `Attribute` *Attribute*. So why are you treating it more like an `enum` or `Map` that can only hold a few values describing something? You don't do it with the classes you uses your custom attributes on! But I don't blame you, it all comes down to some pour choices in wording used by the documentation.

So how should I be think of *Attributes*? As classes naturally. Classes to object that get things done to be more exact. That `#[Route(name: 'home', path: '/')]` like might make more sense when you start looking at it like this: `$route = new Route('/', 'home');`. Here a fun experiment to try; remove the `Attribute` from `Route` then have the `Router` take an array of `Route` parameters as argument. Easy, wasn't it and you understand Attributes and with practice you spot many more classes you can use as such.

Hope that gets you thinking about *Attributes* in a new, more realistic manor that leads to you adding that `#[Attribute]` line to a good many more classes.

== The `Route` Attribute

`Inane\Routing\Route` targets *methods* and may be repeated per controller, one attribute per route.

.Route parameters
[cols="1,1,2,3",options="header"]
|===
|Parameter |Type |Default |Description

|`path`
|`string`
|_required_
|The url path. Placeholders are written `{name}` with an optional regular expression: `{name<regex>}`.

|`name`
|`string`
|`$path`
|Unique route name, used by `Router::url()` and `Router::routeProperty()`.

|`label`
|`string`
|`''`
|A friendly name for the route, handy when building menus and links.

|`methods`
|`HttpMethod[]` or `string[]`
|all methods
|Http methods the route answers to. Strings are converted to `Inane\Http\HttpMethod` cases.

|`extra`
|`null\|array\|Options`
|`null`
|Totally custom values attached to the route, read back with `property()`.
|===

NOTE: Since *1.1.0* `methods` defaults to all http methods: `GET`, `POST`, `PUT`, `DELETE`, `PATCH` and `OPTIONS`.

.Route attribute
[source,php]
----
use Inane\Http\HttpMethod;
use Inane\Routing\Route;

class BlogController {
    #[Route(path: '/blog', name: 'blog-index', label: 'Blog', methods: [HttpMethod::Get])]
    public function indexTask(): array {
        ...
    }

    // the `id` parameter only matches digits
    #[Route(path: '/blog/{id<\d+>}', name: 'blog-post', label: 'Article', extra: ['title' => 'Article {id}'])]
    public function postTask(): array {
        ...
    }
}
----

=== Parameters

A placeholder without a regular expression falls back to `Route::DEFAULT_REGEX` (`[\w\-\.]+`), so it matches a single path segment of word characters, hyphens and periods.

* `hasParams()` - does the path contain any placeholders.
* `fetchParams()` - placeholder names as keys with their regular expression (empty when the default applies) as value.

=== Extra information

Anything placed in `extra` is available through `property()`. The value is treated as a small template, meaning `{name}` tokens are replaced with the parameters supplied.

.Extra information
[source,php]
----
#[Route(path: '/blog/{id<\d+>}', name: 'blog-post', extra: ['title' => 'Article {id}'])]

$route->property('title', ['id' => 7]); // Article 7
$route->property('missing');            // '' (empty string when not set)
----
