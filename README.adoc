= Overview of Attributes
:revnumber: 1.5.0
:revdate: 2026-10-13

What is an *Attribute*? It's a class just like any other class only with the `Attribute` *Attribute*. So why are you treating it more like an `enum` or `Map` that can only hold a few values describing something? You don't do it with the classes you uses your custom attributes on! But I don't blame you, it all comes down to some pour choices in wording used by the documentation.

So how should I be think of *Attributes*? As classes naturally. Classes to object that get things done to be more exact. That `#[Route(name: 'home', path: '/')]` like might make more sense when you start looking at it like this: `$route = new Route('/', 'home');`. Here a fun experiment to try; remove the `Attribute` from `Route` then have the `Router` take an array of `Route` parameters as argument. Easy, wasn't it and you understand Attributes and with practice you spot many more classes you can use as such.

Hope that gets you thinking about *Attributes* in a new, more realistic manor that leads to you adding that `#[Attribute]` line to a good many more classes.

== The `Route` Attribute

`Inane\Routing\Route` targets *methods* and is repeatable: a single controller method may declare multiple routes. Give each route a unique name so each remains independently accessible through the router.

.Route parameters
[cols="1,1,2,3",options="header"]
|===
|Parameter |Type |Default |Description

|`path`
|`string`
|_required_
|The url path. Placeholders are written `{name}` with an optional regular expression: `{name<regex>}`.

|`name`
|`string`
|`$path`
|Unique route name, used by `Router::url()` and `Router::routeProperty()`.

|`label`
|`string`
|`''`
|A friendly name for the route, handy when building menus and links.

|`methods`
|`HttpMethod[]` or `string[]`
|all methods
|Http methods the route answers to. Strings are converted to `Inane\Http\HttpMethod` cases.

|`extra`
|`null\|array\|Options`
|`null`
|Totally custom values attached to the route, read back with `property()`.
|===

NOTE: Since *1.1.0* `methods` defaults to all http methods: `GET`, `POST`, `PUT`, `DELETE`, `PATCH` and `OPTIONS`.

.Route attribute
[source,php]
----
use Inane\Http\HttpMethod;
use Inane\Routing\Route;

class BlogController {
    #[Route(path: '/blog', name: 'blog-index', label: 'Blog', methods: [HttpMethod::Get])]
    public function indexTask(): array {
        ...
    }

    // the `id` parameter only matches digits
    #[Route(path: '/blog/{id<\d+>}', name: 'blog-post', label: 'Article', extra: ['title' => 'Article {id}'])]
    public function postTask(): array {
        ...
    }
}
----

=== Parameters

A placeholder without a regular expression falls back to `Route::DEFAULT_REGEX` (`[\w\-\.]+`), so it matches a single path segment of word characters, hyphens and periods.

* `hasParams()` - does the path contain any placeholders.
* `fetchParams()` - placeholder names as keys with their regular expression (empty when the default applies) as value.

=== URL generation

`getURL(array $parameters = []): string` builds a path directly from a route, without a router or base URI. It replaces placeholders with the supplied values and leaves the route's stored path unchanged.

All placeholders are required. Values must satisfy the complete placeholder regular expression; unconstrained placeholders use `Route::DEFAULT_REGEX`. Missing or invalid values throw `Inane\Routing\Exception\InvalidArgumentException`. Additional parameters are ignored, not appended as a querystring. Values are not URL-encoded.

=== Active state

`active` starts as `false` and is writable. A successful `Router::match()` sets it to `true` on the registered route object, which is also exposed by `RouteMatch::route`. Matching does not automatically reset previously activated routes; reset their state explicitly when reusing a router across requests.

=== Extra information

Anything placed in `extra` is available through `property()`. The value is treated as a small template, meaning `{name}` tokens are replaced with the parameters supplied.

.Extra information
[source,php]
----
#[Route(path: '/blog/{id<\d+>}', name: 'blog-post', extra: ['title' => 'Article {id}'])]

$route->property('title', ['id' => 7]); // Article 7
$route->property('missing');            // '' (empty string when not set)
----

= The Router
:revnumber: 1.5.0
:revdate: 2026-10-13

`Inane\Routing\Router` holds the routes, matches them against the request and builds urls from them.

.Router constructor
[source,php]
----
use Inane\Routing\Router;

$router = new Router(
    routes: [MainController::class],   // controllers and/or route configurations
    baseURI: '/app',                   // part of the uri to exclude when matching
    splitQuerystring: false,           // separate the querystring from the path
);
----

[cols="1,1,2,3",options="header"]
|===
|Parameter |Type |Default |Description

|`routes`
|`array\|OptionsInterface`
|`[]`
|Controller class names carrying `Route` attributes and/or route configuration arrays.

|`baseURI`
|`string`
|`''`
|Part of the uri to strip before matching, useful when the project is served from a subfolder. Also prefixed onto generated urls.

|`splitQuerystring`
|`bool`
|`false`
|When `true` the querystring is removed from the path being matched and its values are parsed into the `query-string` parameter.
|===

== Adding routes

Routes come from two sources, both handled by `addRoutes()`: controller classes using the `Route` attribute, and route configuration arrays keyed by the route name.

.addRoutes
[source,php]
----
$router->addRoutes([
    MainController::class,
    BlogController::class,
    'backups' => [
        'route'  => [
            'path'    => '/archive/{section}/year/{id<\d+>}',
            'methods' => ['GET'],
        ],
        'class'  => HistoryController::class,
        'method' => 'list',
    ],
]);
----

CAUTION: An entry that is neither an existing class nor a configuration array raises an `InvalidRouteException`.

TIP: `setBaseURI()` sets the base uri after construction; both it and `addRoutes()` return the router so calls may be chained.

== Matching a request

`match()` walks the routes in the order they were added and returns a `RouteMatch` for the first route whose path *and* http method satisfy the request, otherwise `null`. Pass a `Inane\Http\Request` to match something other than the current request.

.match
[source,php]
----
if ($match = $router->match()) {
    $controller = new $match->class();
    $controller->{$match->method}($match->params);
}
----

== Building urls

`url()` delegates path generation and parameter validation to the named route's `getURL()` method, then prefixes the router's base URI. Calling `Route::getURL()` directly does not include that prefix. Additional parameters are ignored rather than appended as a querystring; parameter values are not URL-encoded.

.url
[source,php]
----
$router->url('blog-index');                 // /blog
$router->url('blog-post', ['id' => 7]);     // /blog/7
----

Each value is checked against the placeholder's regular expression, so:

* an unknown route name throws an `OutOfRangeException`;
* a missing parameter, or one that fails its regular expression, throws an `InvalidArgumentException`.

== Named-route lookup

`getRoute(string $routeName): ?Route` returns the registered `Inane\Routing\Route` object, or `null` for an unknown name. Unlike `url()` and `routeProperty()`, an unknown name does not raise an `OutOfRangeException`.

The returned object is shared with the router and any corresponding `RouteMatch`. A successful match sets its `active` state to `true`; unsuccessful matches do not activate routes. Previously active routes are not automatically reset on subsequent calls.

== Route properties

`routeProperty()` reaches the `extra` values of a named route, the parameters supplied fill out the value's `{name}` tokens.

.routeProperty
[source,php]
----
$router->routeProperty('blog-post', 'title', ['id' => 7]); // Article 7
----

== Querystrings

With `splitQuerystring` enabled the querystring no longer takes part in the path matching and is instead parsed into the parameters under the `query-string` key.

.splitQuerystring
[source,php]
----
// GET /search?q=robot&page=2
$router = new Router([SearchController::class], splitQuerystring: true);

$match = $router->match();
$match->params['query-string']; // ['q' => 'robot', 'page' => '2']
----

== Exceptions

All exceptions live in the `Inane\Routing\Exception` namespace.

[cols="1,3",options="header"]
|===
|Exception |Thrown when

|`InvalidRouteException`
|A route entry is neither a known class nor a valid configuration.

|`OutOfRangeException`
|The requested route name is not registered.

|`InvalidArgumentException`
|A route parameter is missing or does not match its regular expression.
|===

= The RouteMatch
:revnumber: 1.5.0
:revdate: 2026-10-13

Since *1.4.0* `Router::match()` returns a `Inane\Routing\RouteMatch` describing the route that answered the request.

[cols="1,1,3",options="header"]
|===
|Property |Type |Description

|`class`
|`string`
|Fully qualified controller class.

|`method`
|`string`
|Controller method to call.

|`uri`
|`string`
|The uri used for matching, with the base uri already removed.

|`params`
|`array`
|Values of the path placeholders, plus `query-string` when `splitQuerystring` is enabled.

|`route`
|`Route`
|The matched `Route` itself, giving access to its path, name, methods and extras.

|`template`
|`string`
|View template derived from the class and method names.
|===

.RouteMatch
[source,php]
----
if ($match = $router->match()) {
    $controller = new $match->class();
    $data = $controller->{$match->method}($match->params);

    echo $renderer->render($match->template, $data);
}
----

`routeProperty()` is a shortcut to the matched route's extra information.

[source,php]
----
$match->routeProperty('title', $match->params);
----

== The template

The template is worked out lazily by a parser function: the class' short name and the method name, joined with a directory separator. By default `Controller` is stripped from the class name and `Task` from the method name, so `App\Controller\BlogController::postTask()` becomes `Blog/post`.

Both suffixes are static properties and the whole parser may be replaced by passing a callable to the constructor.

.Customising the template
[source,php]
----
use Inane\Routing\RouteMatch;

// change the stripped suffixes
RouteMatch::$stripClass = 'Action';
RouteMatch::$stripMethod = 'Handler';

// or take over completely
$match = new RouteMatch($route, static fn(string $class, string $method): string => "$class.$method");
----

= Collecting Controllers
:revnumber: 1.5.0
:revdate: 2026-10-13

Listing every controller by hand grows tiresome. `Inane\Routing\AttributeRouteCollector` finds them for you by scanning the filesystem with a glob pattern and hands the result to a `Router`.

.AttributeRouteCollector
[source,php]
----
use Inane\File\Path;
use Inane\Routing\AttributeRouteCollector;

$collector = new AttributeRouteCollector([
    'splitQuerystring' => false,
    'controller'       => [
        'glob'        => 'src/*/*Controller.php',
        'glob_ignore' => '/(Abstract)/',
        'default'     => [WhoopsController::class],
        'path'        => new Path(__DIR__),
    ],
]);

$router = $collector->createRouter();
----

== Configuration

Options are merged over the defaults, so only the differences need to be given.

[cols="1,2,3",options="header"]
|===
|Option |Default |Description

|`splitQuerystring`
|`false`
|Passed to the `Router` created by `createRouter()`.

|`controller.glob`
|`src/*/*Controller.php`
|Glob pattern, relative to `controller.path`, matching the controller files. `GLOB_BRACE` is enabled so `{a,b}` alternatives work.

|`controller.glob_ignore`
|`/(Abstract)/`
|Regular expression tested against each filename; matches are skipped.

|`controller.default`
|`[]`
|Controllers and route configurations appended to the collected list; duplicates are removed.

|`controller.path`
|`new Path()`
|Search path for the glob, either a `Inane\File\Path` or a string.
|===

== Methods

* `collect()` - the controller classes and route configurations as an `Options` collection.
* `collectInto(Router $router)` - adds the collected routes to an existing router and returns it.
* `createRouter(string $baseURI = '')` - creates a router, honouring `splitQuerystring`, populated with the collected routes.

.Collecting into an existing router
[source,php]
----
$router = new Router([StaticController::class]);
$collector->collectInto($router);
----

NOTE: Classes are read from the matched files, so the files need only be reachable; the autoloader is left to load them when the routes are parsed.

= Example: Simple
:revnumber: 1.5.0
:revdate: 2026-10-13

Super simple example using *php* built in web server. +
We create a class, let's call it *MainController.php*, and add `Route` *attributes* to the methods we want routes to. The *path* is matched against the *url* with *regex*.

.MainController.php
[source,php]
----
class MainController {
    ...

    #[Route(path: '/', name: 'home')]
    public function home(): void {
        ...
        echo <<<HTML
...
HTML;
    }

    ...

    #[Route(path: '/product/{product}', name: 'product', )]
    public function productTask(array $params): void {
        $sql = "...where product_id = '{$params['product']}'";
        ...
        echo <<<HTML
...
HTML;
    }

    ...
}
----

Our "application" sits in *index.php* which will pass through existing files and try route everything else. +
We simply add our *MainController* to the `Router` and then check for a match.

.index.php
[source,php]
----
use App\Controller\MainController;
use Inane\Routing\Router;

require_once 'vendor/autoload.php';

$file = 'public' . $_SERVER['REQUEST_URI'];

// Server existing files in web dir
if (file_exists($file) && !is_dir($file)) return false;

$router = new Router();
// Add the controllers to the Router
$router->addRoutes([MainController::class]);

if ($match = $router->match()) { // Check for a Route Match
    // create the controller
    $controller = new $match->class();
    // and call the method with parameters.
    $controller->{$match->method}($match->params);
} else { // Otherwise do what ever else, we'll throw an error.
    throw new Exception('Request Error: Unmatched `file` or `route`!');
}
----

Now let's fire up php's built in server:

.php built-in server
`php -S localhost:8080 -t public index.php`

All that's left is to visit the url in your favourite browser. +
And that's a real basic example of how it's done and it doesn't really get much more complex.

Again we set up our routes by using attributes on the controller methods.

.IndexController.php
[source,php]
----
class IndexController extends AbstractController {
    ...

    #[Route(path: '/', name: 'home')]
    public function indexTask(): array {
        ...
    }

    ...

    #[Route(path: '/product/{product}', name: 'product', )]
    public function productTask(): array {
        ...
    }

    ...

    #[Route(path: '/product/{product}/review/{id<\d+>}', name: 'product-review')]
    public function reviewTask(): array {
        ...

    ...

But now we're adding a view template to the mix. Not that this does much, but it's just for show. So here we render an anchor.

== Putting it all together

Chuck that all into an app, I'm only showing the parts relevant to the routing.

.Application.php
[source,php]
----
class Application {
    ...

    protected function initialise(): void {
        ...
        $this->router = new Router([
            IndexController::class,
            ...
            WhoopsController::class,
            ...
        ]);
        ...
    }

    ...

    public function run(): void {
        ...
        if ($match = $this->router->match()) {
            $controller = new $match->class($match->params);
            $data = $controller->{$match->method}();
            ...
            // since 1.4.0: using the RouteMatch we can now easily get the template
            $body = $this->renderer->render($match->template, $data);
            ...
        }
        ...
    }

    ...
}
----

... and you're of to the races.

= Example: Collected
:revnumber: 1.5.0
:revdate: 2026-10-13

The same application, only the controllers are no longer listed by hand; the `AttributeRouteCollector` goes looking for them.

.Application.php
[source,php]
----
use Inane\File\Path;
use Inane\Routing\AttributeRouteCollector;

class Application {
    ...

    protected function initialise(): void {
        ...
        $this->router = (new AttributeRouteCollector([
            'splitQuerystring' => true,
            'controller'       => [
                // every *Controller.php one level down from src
                'glob'        => 'src/*/*Controller.php',
                // except the abstract ones
                'glob_ignore' => '/(Abstract)/',
                // and these, wherever they may live
                'default'     => [WhoopsController::class],
                'path'        => new Path(dirname(__DIR__)),
            ],
        ]))->createRouter();
        ...
    }

    ...

    public function run(): void {
        ...
        if ($match = $this->router->match()) {
            $controller = new $match->class($match->params);
            $data = $controller->{$match->method}();
            ...
            $body = $this->renderer->render($match->template, $data);
            ...
        }
        ...
    }

    ...
}
----

Drop a new controller into `src`, mark its methods with `Route` attributes and it is routed; no configuration to remember.

= Appendix: .htaccess
:revnumber: 1.5.0
:revdate: 2026-10-13

You will also need to do some magic in your `.htaccess` file so that `index.php` handles all requests.

[source,apache]
----
RewriteEngine On
# The following rule tells Apache that if the requested filename exists, simply serve it.
RewriteCond %{REQUEST_FILENAME} -s [OR]
RewriteCond %{REQUEST_FILENAME} -l [OR]
RewriteCond %{REQUEST_FILENAME} -d
RewriteRule ^.*$ - [L]

# The following rewrites all other queries to index.php. The
# condition ensures that if you are using Apache aliases to do
# mass virtual hosting or installed the project in a subdirectory,
# the base path will be prepended to allow proper resolution of
# the index.php file; it will work in non-aliased environments
# as well, providing a safe, one-size fits all solution.
RewriteCond %{REQUEST_URI}::$1 ^(/.+)/(.*)::\2$
RewriteRule ^(.*) - [E=BASE:%1]
RewriteRule ^(.*)$ %{ENV:BASE}/index.php [L]

<Limit GET HEAD POST PUT DELETE OPTIONS>
# Deprecated apache 2.2 syntax:
# Order Allow,Deny
# Allow from all
# Apache > 2.4 requires:
Require all granted
</Limit>
----
